# Implementation Plan: Release Distribution and Auto-Update

**Branch**: `005-release-distribution` | **Date**: 2026-10-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-release-distribution/spec.md`

## Summary

Friends install Sonata from a prebuilt universal disk image on GitHub Releases, and the app
updates itself after confirmation. A tag-triggered workflow reuses CI checks on Linux, then builds
the universal, ad-hoc signed app (with a universal `sonata` CLI) on a macOS runner, signs the
update archive with the project's own key, publishes the release, and uploads a `latest.json`
manifest generated by a tested script. The app uses the official Tauri updater plugin; core owns
the schedule, preference, and banner state; the sidebar shows a banner. `install.sh` offers
rustup. The repository becomes public (the maintainer flips visibility by hand).

## Technical Context

**Language/Version**: Rust 2024 edition (stable), TypeScript 5 / React 19, POSIX sh, Node 22 (release script)

**Primary Dependencies**: Tauri 2.12, new `tauri-plugin-updater` 2; GitHub Actions with `gh` (preinstalled), no third-party release action

**Storage**: `~/.sonata/preferences.json` gains `autoUpdateCheck` (serde default `true`; no schema bump)

**Testing**: `cargo test` (core schedule and banner state), vitest (banner component, `latest-json.mjs`), shell tests for `check-version.sh` and `install.sh` prompt (stubbed `PATH`), manual end-to-end per quickstart

**Target Platform**: macOS 15+, Apple Silicon and Intel (universal binary)

**Project Type**: desktop app + CLI + release automation

**Performance Goals**: release published < 30 min after tag push (SC-003); update install < 1 min (SC-004)

**Constraints**: zero paid services; private key never in repo, logs, or argv; user data untouched by updates

**Scale/Scope**: a few releases per month, tens of users

## Complexity Tracking

| Addition | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| `tauri-plugin-updater` dependency | Signed download, verification, and bundle replacement (FR-010, FR-011) | Own updater: reimplements signature checks and bundle swap; higher risk |
| `latest-json.mjs` (Node script in CI) | Manifest must be generated and tested (constitution III) | Third-party `tauri-action`: write token handed to external code (R5) |
| `scripts/build-cli.sh` | Universal CLI inside the bundle (FR-002) | Inline npm script cannot branch on target cleanly |
